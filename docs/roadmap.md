## フェーズ 4 の進め方

設計はまとめて決め、実装は機能ごとに縦に進める。DB・画面・機能を種類ごとにまとめて作ると、使い方が決まる前の列を足したり、同じ画面を何度も作り直したりするため。

```
① 方向を決める  ∥  ② 土台を作り直す
        ↓
③ アプリの骨組みを変える → ④ 機能を 1 つずつ縦に足す → ⑤ 仕上げ
```

| 段階                               | 主な作業                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 方向を決める（コードは書かない） | ・**父に実際に使ってもらいフィードバック収集**<br>・ウイスキーのデータセットの調査（マスタ・候補検索・入力補完ができるか）<br>・要件の 5 章・データモデル全体（マスタ・製品・ボトル・テイスティングノートの関係）・画面の一覧と遷移・見た目を決め直し、モックを作り直す<br>・③ と ④ の Issue を起票する                                                               |
| ② 土台を作り直す（① と並行）       | ・ADR：書き込みを Server Actions にし、読み書きをデータアクセス層に集め、機能ごとのフォルダに置く（ADR-0002・ADR-0011 を置き換え）<br>・ファイルの置き場所を移す（#134）→ Server Actions へ移す<br>・データアクセス層に移した読み取り（一覧・傾向）にも、テスト用 DB のテストを足す                                                                                   |
| ③ アプリの骨組みを変える           | ① のモックに沿って、全画面にかかる変更を 1 回で入れる（ログイン後の着地・タブとヘッダーの構成・製品とボトルの階層・デザインの値）<br>・見た目に関わる小さな Issue もここで決める（#99・#128・#135）                                                                                                                                                                   |
| ④ 機能を 1 つずつ縦に足す          | 1 つの Issue に、マイグレーション・読み書き・画面をまとめる。順番は ① で決めた依存に従う<br>・写真アップロード（実装先を ADR で決めてから着手）・一覧の検索・フィルタ・並べ替え・ページネーション・PWA 化（`app/manifest.ts` ＋アイコン）など<br>・フィードバック反映・バグ修正<br>・Issue（#90・#106・#107・#117・#120・#130・#131）は、新しい画面で前提を確かめ直す |
| ⑤ 仕上げ                           | ・レスポンシブデザイン（`lg` でサイドバー＋グリッド 3〜4 列）。機能が固まってから、まとめて入れる<br>・**E2E（Playwright・主要フロー 1 本）＋テスト拡充**<br>・**開発環境の Docker 化**（`docker compose up` でアプリ＋ローカル DB が立ち上がる。本番は Vercel のまま変えない）<br>・README 整理（スクショ・デモ GIF）・アーキ図<br>・予備日                          |
